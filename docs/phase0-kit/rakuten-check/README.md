# 楽天照合ツール

KeepaでエクスポートしたCSVを読み込み、商品ごとに楽天市場の最安値を楽天の公式API
（楽天商品検索API）で探して、利益計算とA/B/C判定までをまとめて行うWebページ。
セラーリサーチの②③④（Keepa確認→Astraの楽天確認→統合・analyze.py）を1画面にまとめた
もので、Astraへの依頼・CSVの転記・スクリプトの実行が不要になる（2026-09-25追加）。

Amazonへのアクセスは一切しない。通信先は楽天の公式APIだけ。

## 公開場所

GitHub Pagesで公開して使う（楽天APIは「登録したWebサイトから呼ばれたとき」だけ
応答する仕様のため、ファイルを直接開くのではなく公開URLから開く必要がある）。

- URL：`https://tohaya0216.github.io/github_actions_test/phase0-kit/rakuten-check/`
- GitHub Pagesの設定：リポジトリのSettings → Pages → Source「Deploy from a branch」、
  ブランチはこのツールがあるブランチ、フォルダは`/docs`

## 楽天APIの登録（初回のみ）

1. [楽天ウェブサービス](https://webservice.rakuten.co.jp/)に楽天会員でログインし、アプリを新規登録する
2. 「許可されたWebサイト」に `tohaya0216.github.io` を登録する
3. 発行された「アプリケーションID」と「アクセスキー」（`pk_`で始まる）を、ツールの「1. 楽天APIの設定」に入力して保存する
4. 「接続テスト」で確認する

入力したIDとキーはブラウザのlocalStorageにだけ保存され、リポジトリには含まれない。

## 判定のしかた

判定基準は`../analyze.py`と同じ（利益率20%以上・粗利1,000円以上・月3個以上・
-20%値下がりでも黒字・出品者数3人以上・Amazon本体の出品なし・有名ブランドでない・
出品者数の急増なし）。加えて、楽天側の次の点を警告し、A判定にしない：

- 商品説明に「転売」「業者様」等の記載がある（転売お断りの可能性）
- 送料別（利益が送料分減る）
- 楽天の店名がAmazonのセラー名と似ている（価格同期の可能性）

Amazon側の情報だけで不合格が決まる商品（Amazon本体が出品中、有名ブランドなど）は、
楽天APIを呼ばずにC判定にして呼び出し回数を節約する。

## 限界

- 型番の一致判定は商品名の文字列比較。**A判定の商品は、必ず楽天の商品ページを開いて
  同じ商品か目で確認する**こと
- 型番が分からない商品（KeepaのModel列が空で、商品名にも型番らしき文字がない）は照合できない
- Keepaの列名は言語設定などで変わる可能性がある。自動判定が外れたら、画面の
  「列の対応」で選び直す
- ポイントは「商品のポイント倍率＋上乗せ分」で計算している。キャンペーン等は含まない
