# 楽天照合ツール

KeepaでエクスポートしたCSVを読み込み、商品ごとに楽天市場の最安値を楽天の公式API
（楽天商品検索API）で探して、利益計算とA/B/C判定までをまとめて行うWebページ。
セラーリサーチの②③④（Keepa確認→Astraの楽天確認→統合・analyze.py）を1画面にまとめた
もので、Astraへの依頼・CSVの転記・スクリプトの実行が不要になる（2026-09-25追加）。

Amazonへのアクセスは一切しない。通信先は楽天の公式APIだけ。

## 公開場所

GitHub Pagesで公開して使う（楽天APIは「登録したWebサイトから呼ばれたとき」だけ
応答する仕様のため、ファイルを直接開くのではなく公開URLから開く必要がある）。

- URL：`https://tohaya0216.github.io/github_actions_test/phase0-kit/rakuten-check/`
- GitHub Pagesの設定：リポジトリのSettings → Pages → Source「Deploy from a branch」、
  ブランチはこのツールがあるブランチ、フォルダは`/docs`

## 楽天APIの登録（初回のみ）

1. [楽天ウェブサービス](https://webservice.rakuten.co.jp/)に楽天会員でログインし、アプリを新規登録する
2. 「許可されたWebサイト」に `tohaya0216.github.io` を登録する
3. 発行された「アプリケーションID」と「アクセスキー」（`pk_`で始まる）を、ツールの「1. 楽天APIの設定」に入力して保存する
4. 「接続テスト」で確認する

入力したIDとキーはブラウザのlocalStorageにだけ保存され、リポジトリには含まれない。

## 判定のしかた

判定基準は`../analyze.py`と同じ（利益率20%以上・粗利1,000円以上・月3個以上・
-20%値下がりでも黒字・出品者数3人以上・Amazon本体の出品なし・有名ブランドでない・
出品者数の急増なし）。加えて、楽天側の次の点を警告し、A判定にしない：

- 商品説明に「転売」「業者様」等の記載がある（転売お断りの可能性）
- 送料別（利益が送料分減る）
- 楽天の店名がAmazonのセラー名と似ている（価格同期の可能性）

Amazon側の情報だけで不合格が決まる商品（Amazon本体が出品中、有名ブランドなど）は、
楽天APIを呼ばずにC判定にして呼び出し回数を節約する。

楽天ではまず**型番**で探し、同じ型番の商品が見つからなければ**JANコード**
（KeepaのEAN列）でもう一度探す。JANで見つけた商品は、結果の店名の横に
「JANで一致」と表示される。

## 利益の計算式

利益 ＝ Amazon価格 − 実質仕入れ値 −（Amazon価格×販売手数料率 ＋ FBA手数料 ＋ 基本成約料）×1.1

- 実質仕入れ値 ＝ 楽天価格 ×（1 − ポイント率）。ポイント率は「商品のポイント倍率＋上乗せ分」
- 販売手数料率・FBA手数料は、KeepaのCSVに列があればそれを使う。なければ15%・仮の値（既定500円）で計算し、A判定にしない
- 基本成約料は小口出品で1個100円（税抜）。大口出品に切り替えたら画面で0にする
- ×1.1は、Amazonの手数料が税抜表示で実際には消費税10%が上乗せされる分（画面で外せる）。
  Phase 1で実際の手数料と比べ、二重に数えていたら外す（`analyze.py`は`CONFIG`の`FEE_TAX_RATE`）
- 2026年4月から、販売価格750円超の商品は販売手数料率が0.4%上がっている。
  KeepaのCSVの値が古いと差が出るので、A判定の商品はFBA料金シミュレーターで確認する

## セラー評価の目安

結果の上に、そのセラーの`quality_rating`の目安を表示する。AirtableのWatchlistに
書き戻すときの参考にする（楽天で同じ商品が見つかった件数が3件未満なら判断しない）。

| 目安 | 条件 |
|---|---|
| S | A判定が2件以上 |
| A | A判定が1件、またはB判定が3件以上 |
| B | A判定はなく、B判定が1〜2件 |
| C | A判定もB判定もない |

S/Aのセラーは定点観測を続け、B/Cは`status`を`excluded`にして追わない
（`../seller-research/README.md`の「質による絞り込み運用」と同じ考え方）。

## これまでの結果を集計する

画面の「6. これまでの結果を集計する」で、「結果をCSVで保存」したファイルを複数まとめて
選ぶと、セラーごとの成績と、この手法を続けるべきかの目安を出す。

- 通過率＝A判定 ÷ 楽天で同じ商品が見つかった件数（Amazon側だけで見送った商品は分母に入れない。
  `dennou-sedori-tips.md` 15-4の通過率は「両モールの価格が分かった候補」が分母なので、それに揃えている）
- 判断の目安：8%以上＝有望（15-4の「15%前後」）、2〜8%＝効率化が前提（「3%前後」）、
  2%未満＝手法を再考（「0〜1%」）。照合できた商品が20件未満のうちは判断しない
- 画面で「このCSVの作業時間」を入れておくと、「A/時」（作業1時間あたりのA判定の件数）と
  「見込み利益/時」（A判定の商品が1個ずつ売れた場合の利益の合計 ÷ 作業時間）も出す。
  `dennou-sedori-tips.md` 15-5の先行指標にあたる
- 保存するCSVには`seller_name`（画面で入力したセラー名）と`checked_at`（日付）が入る。
  セラー名を入れ忘れると「（セラー名なし）」としてまとめられる

## 付属品・部品の取り違え対策（2026-09-25、実データの試験で発覚）

型番は本体だけでなく、交換バンド・パッキン・対応ケーブルなどの商品名にも入っている。
安い順に検索すると付属品が上位を埋め、付属品の価格で利益を計算したり、本体が
検索結果に入らなかったりした。そのため次の3つで防いでいる：

- 楽天の検索で、Amazon価格の30%未満の商品を最初から除く（`CONFIG.MIN_RAKUTEN_PRICE_RATIO`）
- 楽天の商品名に「互換」「交換」「部品」「専用」「対応」「バンド」「パッキン」「ケース」
  「アダプタ」「充電器」「電源」「ケーブル」、英語の「for」などがあり、**Amazonの商品名には
  ない**ものは付属品とみなし、一致にしない（`ACCESSORY_WORDS`）。Amazonで売っている商品自体が
  アダプター等なら、楽天の同じ種類の商品は除かない。「中古」「ジャンク」「訳あり」「アウトレット」は
  常に除く（`CONDITION_WORDS`）。実データでは「Boss DS-1用 電源アダプタ」がDS-1本体と一致していた
- 楽天の価格がAmazonの半額未満なら「別商品・付属品・セット数違いの可能性」と警告し、A判定にしない

さらに、型番だけで検索すると楽天が「DS」「1」のように細かく分けて検索し、無関係な商品で
結果が埋まって本体が見つからないことがあった（BOSS DS-1・CASIO F-91W）。そのため：

- 検索語は「ブランド名＋型番」→「型番だけ」→「JAN」の順に試す
- 楽天の並び順は関連度順にし、型番が一致したものの中から最安値を選ぶ
- 検索する価格帯を「Amazon価格の30%〜100%」に絞る（100%超は仕入れても利益が出ない）

別メーカーが同じ型番を使っていることもある（BOSS DS-1 に「サンカ ドラム缶オープナー DS-1」が
一致した）。そのため、KeepaのBrand列とAmazonの商品名の先頭の語（「サーモス」「マキタ(Makita)」
など）をブランド名の候補にし、型番が一致したもののうち**ブランド名も商品名にあるものを優先**する。
ブランド名を含むものが1つもなければ、型番だけ一致したものを表示するが「別メーカーの同じ型番の
可能性」と警告してA判定にしない。

## 限界

- 型番の一致判定は商品名の文字列比較。**A判定の商品は、必ず楽天の商品ページを開いて
  同じ商品か目で確認する**こと
- 型番が分からない商品（KeepaのModel列が空で、商品名にも型番らしき文字がない）は照合できない
- Keepaの列名は言語設定などで変わる可能性がある。自動判定が外れたら、画面の
  「列の対応」で選び直す
- ポイントは「商品のポイント倍率＋上乗せ分」で計算している。キャンペーン等は含まない

## ファイル

| ファイル | 用途 |
|---|---|
| `index.html` | 画面 |
| `app.js` | 画面の動作と楽天APIの呼び出し |
| `logic.js` | CSV読み込み・型番照合・利益計算・判定（画面から独立。Node.jsでテスト可能） |
| `claude-in-chrome-prompt-product-finder.md` | Keepa製品ファインダーでの絞り込みとCSV書き出しを「Claude in Chrome」に任せる指示文 |
| `astra-prompt-verify-candidates.md` | A/B判定の商品の楽天側の最終確認をAstraに任せるプロンプト |
| `test_logic.js` | `logic.js`のテスト。`node test_logic.js`で実行（外部ライブラリ不要） |

判定基準を変えるときは、`logic.js`の`CONFIG`と`../analyze.py`の`CONFIG`を両方直し、
`node test_logic.js`が通ることを確認する。
