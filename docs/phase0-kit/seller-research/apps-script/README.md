# セラーウォッチ検出：共有データストアのセットアップ（Google Apps Script版・廃止）

PC拡張機能・Kiwi Browser拡張機能・スマホのブックマークレットが、全部同じ
Googleスプレッドシートにデータを読み書きするようにするための設定。これで
「PCで見たセラーをスマホでまた検出してしまう」といった重複がなくなる。

Amazonへの通信は一切増えない。通信先はGoogleのサーバー（script.google.com）
だけなので、Amazon側のボット検知・アクセス制限とは無関係。

## セットアップ手順（初回のみ・15分程度）

### 1. Googleスプレッドシートを作る

1. [sheets.google.com](https://sheets.google.com) で新しい空のスプレッドシートを作成
2. 名前を分かりやすいものにする（例：「セラーウォッチDB」）
3. シートの中身（タブ）は空のままでよい。**スクリプトが初回アクセス時に
   自動で「Seen」「Watchlist」の2タブを作る**

### 2. Apps Scriptを貼り付ける

1. メニューの「拡張機能」→「Apps Script」を開く
2. デフォルトで開いている`Code.gs`の中身を全部消し、この`apps-script/Code.gs`
   の内容をそのまま貼り付ける
3. 上の方にある `SHARED_SECRET` の値を、**自分だけが知っている適当な文字列**
   に変更する（例：`kotetsu-sw-2026-xyz123` のような、他人が推測しにくいもの。
   これは本格的な認証ではなく簡易的な保護なので、パスワードほど厳重でなくてよい
   が、他人には教えない）
4. 保存する（フロッピーディスクのアイコン、またはCtrl+S）

### 3. ウェブアプリとしてデプロイする

1. 右上の「デプロイ」→「新しいデプロイ」をクリック
2. 歯車アイコン（種類の選択）→「ウェブアプリ」を選ぶ
3. 「次のユーザーとして実行」：**自分（あなたのGoogleアカウント）**
4. 「アクセスできるユーザー」：**全員**
   （※ここを「全員」にしないと拡張機能・ブックマークレットからアクセスできない。
   ただしSHARED_SECRETを知らない相手はデータの閲覧・書き込みができない設計なので、
   実質的な保護はかかっている）
5. 「デプロイ」をクリック
6. 初回は権限の承認画面が出るので、自分のGoogleアカウントで承認する
   （「このアプリは確認されていません」という警告が出ることがあるが、
   自分が書いた・自分だけが使うスクリプトなので「詳細」→「（プロジェクト名）に移動」
   で進めてよい）
7. 発行された「ウェブアプリのURL」（`https://script.google.com/macros/s/.../exec`
   の形式）をコピーする

### 4. 拡張機能・ブックマークレットに設定する

コピーした**ウェブアプリのURL**と、さっき決めた**SHARED_SECRET**の2つを、
以下の場所に設定する：

- **PC/Kiwi拡張機能**：ツールバーアイコン→ポップアップの設定欄にURL・シークレットを貼り付けて保存
- **ブックマークレット**：初回実行時に`prompt()`でURL・シークレットの入力を求められるので、
  そこで入力する（以後はスマホの`localStorage`に保存され、再入力不要）

## コードを更新したいとき

`Code.gs`の内容を修正したら、Apps Scriptエディタで保存し、再度
「デプロイ」→「デプロイを管理」→鉛筆アイコン→バージョン「新バージョン」を選んで
「デプロイ」する（URLは変わらない）。

## データを直接確認したいとき

スプレッドシートを直接開けば、「Seen」「Watchlist」タブに今のデータが
リアルタイムで見える。Claudeや拡張機能を経由しなくても、スプレッドシート
アプリ（スマホアプリ含む）から直接確認・手動編集ができる。

## トラブルシューティング

### Google Driveの「現在、ファイルを開くことができません」が出る

Apps Scriptエディタを開こうとした時や、ウェブアプリのURLに直接アクセスした
時にこのエラーが出ることがある。**ブラウザに複数のGoogleアカウントが同時に
ログインしていると発生しやすい**（Googleがどのアカウントで開くべきか混乱する
ため）。シークレットウィンドウ（1アカウントだけでログイン）で開き直すと
解消することが多い。

### 拡張機能の「接続テスト」で `Unexpected token '<'` エラーが出る

JSONの代わりにHTML（Googleのログイン・アカウント選択ページ）が返ってきている
サイン。上記と同じ複数アカウント問題が、拡張機能の通信（`fetch()`）にも
影響していることが多い。**`fetch()`はデフォルトでは別オリジン（クロスオリジン）
宛てのリクエストにログインCookieを付けない**ため、`content.js`・`popup.js`・
ブックマークレット側で`credentials: "include"`を明示的に指定し、Cookieを
一緒に送るようにしている（2026-09-23対応）。この対応済みのバージョンを
使っているか確認すること（`content.js`内の`VERSION`が`0.3.1`以降）。

それでも解消しない場合は、Chromeの「シークレットモードでの実行を許可する」を
その拡張機能に対して有効にし（`chrome://extensions`→対象拡張機能の詳細）、
シークレットウィンドウでAmazonを開いて使う方法もある。
