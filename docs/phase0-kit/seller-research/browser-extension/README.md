# セラーウォッチ検出 拡張機能（個人用・未検証）

①セラーリスト作成（`../README.md`参照）を支援する、Amazon商品ページ・出品者ページ
向けのブラウザ拡張機能（Chrome/Edge、Manifest V3、開発者モードで読み込む個人用ツール）。

## できること

Amazon.co.jpの商品ページ（他の出品者パネル）や出品者ストアページを**通常通り開いた
だけ**のタイミングで、そのページに表示されている出品者情報を読み取り、

- 評価数が条件レンジ内（デフォルト50〜400件、ポップアップで変更可）
- まだこの拡張機能でチェックしていない（新規）

の両方を満たすセラーを見つけたら、画面右下に確認バナーを出す：

> 条件に合致するストアが見つかりました
> （店名）（評価◯件）
> 監視リストに追加しますか？　[追加する] [今回は追加しない]

「追加する」を押すと、共有データストア（Airtable、下記参照）のWatchlist
テーブルに、`seller-watchlist-template.csv`と同じ列構成で1行追加される
（`category_tendency`・`quality_rating`は空欄のまま出力される。これらは②③④の
評価を経てから埋める列のため、拡張機能の役割はあくまで①の入口を広げることに
限定している）。

## 共有データストア（PC・Kiwi・ブックマークレットでデータを共有、2026-09-23追加）

PCの拡張機能・Kiwi Browserの拡張機能・スマホのブックマークレットが、それぞれ
別々にデータを持っていると、「PCで既にチェックしたセラーをスマホでまた検出
してしまう」といった不便がある。これを解消するため、判定履歴（Seenテーブル）・
監視リスト（Watchlistテーブル）を**Airtable経由で保存**し、全端末で共有する。

（最初はGoogle Apps Script + スプレッドシートで実装したが、Googleアカウントが
複数ログインしている環境で「意図しないアカウントに振り分けられて404になる」
問題が実機で解消できず、Googleアカウントに依存しないAirtableに切り替えた。
経緯は`../apps-script/README.md`参照）

セットアップ手順は`../airtable/README.md`参照。設定は拡張機能のポップアップ
（ツールバーアイコン→Base ID・Personal Access Tokenを入力→保存）で行う。
未設定の場合、ページを開いても「共有データストア未設定」という表示が出るだけで、
判定自体は動かない。

**Amazonへの追加通信は増えない。** 通信先はAirtableのサーバー
（api.airtable.com）のみで、これはAmazon側のボット検知・アクセス制限とは
無関係。

## 動いているか分かるようにする表示（2026-09-23追加）

条件に合うセラーが見つからないと画面上に何も表示されず、「拡張機能がそもそも
動いているのか」が分からず判断に困る、という問題があったため、**対応ページを
開くたびに、画面左上に小さな状態表示が必ず出る**ようにした（マッチの有無に
関わらず）。6秒ほどで自動的に消える。表示内容の例：

- `SW: スキャン中…`（実行開始の合図）
- `SW: このページではセラー情報が見つかりませんでした`（対象要素が0件。
  ページ構造が想定と違う可能性が高い＝`content.js`の調整が必要なサイン）
- `SW: 3件検出（新規2・既知1・範囲外1・評価数不明0）／条件合致なし`
  （セラー情報は見つかったが、評価数レンジ外だった等で確認バナーは出なかった、
  という内訳。これが出ていれば**拡張機能自体は正常に動いている**証拠になる）

これで「そもそも動いていない」のか「動いているが条件に合わないだけ」なのかを
画面を見ただけで区別できる。

## メーカー・代理店直販の注意表示（2026-09-23追加）

バッチ3の実測で、「エフェクター専門店ナインボルト」という店名のセラーが、実際には
楽天・Amazon両方に自ら出品して価格を同期させている（＝電脳せどりの利益源となる
価格差が構造的に存在しない）ケースが見つかった。この教訓を踏まえ、店名に
「専門店」「代理店」「正規販売店」「メーカー公式」等のキーワードが含まれるセラーを
検出した場合、確認バナーに黄色い注意書きを追加で表示するようにした
（`content.js`の`VENDOR_KEYWORDS`）。

これは追加の通信を発生させない、既に読み取り済みの店名テキストに対する
単純な部分一致チェックであり、判定をブロックするものではない（あくまで注意喚起）。
警告が出た場合は、楽天側にも同一店舗が出品していないか（店名で検索するだけでよい）を
先に確認し、同一なら価格計算をする前にそのセラーを見送るのが効率的。

## 通信・規約リスクについて

**Amazonへの追加通信は一切行わない。** 現在開いているページのDOM
（画面に表示されている内容そのもの）を読み取るだけで、裏でセラーのストアページを
自動取得するようなことはしない（判定範囲を「評価数のみ」にした理由）。
Amazonへの負荷・ボット検知の観点では、あなたが普段通りページを開く操作に
上乗せして動くだけなので、通常のブラウジングと変わらない。共有データストア
（Airtable）への通信は発生するが、これはAmazonとは別のサーバー
（api.airtable.com）宛てなので、Amazon側の検知とは無関係。

## 動作確認済み（2026-09-23）

実機（Android・Kiwi Browser）で、スマホ版Amazonの「その他の出品」ページから
実際に複数セラーを検出できることを確認済み。当初は開発環境からAmazonへの
通信がブロックされていたため未検証だったが、実際に動作することが分かった。

検証の過程で「ステータス表示自体が再スキャンを誘発し、表示がちらつく／
本来新規のはずのセラーが既知と誤表示される」という自己ループのバグが
見つかり、修正済み（`withoutTriggeringRescan`で自分自身のDOM操作中は
MutationObserverを一時停止するようにした）。

それでも、Amazonのページ構造は今後変わる可能性があり、`content.js`の
セレクタ・正規表現（`aod-offer`系ID、「◯件の評価」等の文言パターン）が
将来動かなくなることはあり得る。バナーが出ない・検出できない場合は、
Chrome DevTools（Kiwi Browserなら拡張機能一覧から開ける）のConsoleタブで
`[seller-watch]` から始まるログを確認してほしい。

## 既知の制約：「他の出品を見る」一覧では評価数が読み取れないことがある（2026-09-24）

実機での検証で、「他の出品を見る」パネルには**評価件数（「◯件の評価」）が
表示されない**ケースがあることが分かった。この場合、そのパネル内のセラーは
全員「評価数不明」判定になり、確認バナーが出ないままSeenテーブルに記録される
（＝仕組み上は正常動作だが、実質的にこの画面からは候補が見つからない）。

評価件数は**出品者ストアページ（店名をタップして開くページ）には表示される**
ため、条件に合うセラーを探したいときは、そちらを開いて確認する方が確実。
将来的に一覧パネル側でも評価数を取得できる表示パターンが見つかれば
`extractRatingCount`の対応パターンを追加する。

## 実機で見つかった不具合の修正（2026-09-24）

Kiwi Browserでの実運用中に見つかった3つの問題を修正済み（VERSION 0.5.1）：

- 店名が「詳細を見る」等の無関係なリンクのテキストで保存される
  （`querySelector`のカンマ区切りセレクタがDOM出現順でマッチする仕様が原因。
  優先順位通りに1つずつ試すよう修正し、明らかな誤取得を弾く保険も追加）
- 条件に合う候補が複数あっても最初の1件しか確認されない
  （全候補をキューに入れ、1件ずつ順番に確認するよう修正）
- 追加/スキップ後に保存できたか画面から分からない
  （ステータス表示に結果を出すよう修正）
- Amazonの「他の出品を見る」パネルはスクロール中に何度もDOMが書き換わり、
  そのたびに再スキャン＆Seenテーブル全件取得が走って表示がちらついていた
  問題を緩和（再スキャンの間隔を500ms→1200msに延長し、Seenテーブルの取得結果を
  15秒間キャッシュするように変更）

## インストール方法（開発者モード）

Chrome Web Storeには公開しない、ローカル読み込み専用の個人用拡張機能。
PCのChrome/EdgeでもKiwi Browserでも手順は同じ。

1. 先に`../airtable/README.md`の手順で共有データストアを準備し、
   Base ID・Personal Access Tokenを控えておく
2. `chrome://extensions` を開く
3. 右上の「デベロッパーモード」をONにする
4. 「パッケージ化されていない拡張機能を読み込む」をクリックし、この
   `browser-extension` フォルダを選択する
5. ツールバーアイコン→ポップアップを開き、Base ID・Personal Access Tokenを
   入力して保存する（「接続テスト」で確認できる）
6. Amazon.co.jpの商品ページ（「他の出品を見る」を開いた状態）や、
   出品者名をクリックして開くストアページ（URLに`?seller=...`を含む）で
   動作確認する

## ファイル一覧

| ファイル | 用途 |
|---|---|
| `manifest.json` | 拡張機能の定義（Manifest V3） |
| `content.js` | ページ内のセラー情報を読み取り、確認バナーを表示するメインロジック |
| `styles.css` | 確認バナー・ステータス表示の見た目 |
| `popup.html` / `popup.js` | ツールバーアイコンから開く操作パネル（共有データストアの設定・接続テスト・条件設定・履歴リセット） |

## 使い方の流れ（①との接続）

1. 普段通りAmazonで商品ページを巡回する（既存のリサーチ作業のついででよい）
2. 条件に合うセラーが見つかったら都度「追加する」を押す（共有データストアに
   即座に保存される）
3. たまったデータは、Airtableのベースを直接開けばいつでも確認できる。
   `../seller-watchlist.csv`へ転記したい場合は、Watchlistテーブルの行を選択して
   CSV形式でエクスポートできる（`quality_rating`等は空欄のまま。これは②③④の
   評価を経てから埋める）
