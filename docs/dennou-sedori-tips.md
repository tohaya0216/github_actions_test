# 電脳せどり 完全ノウハウまとめ

YouTube解説動画（21本サーベイ）や専門メディアの記事を横断的にリサーチし、電脳せどり
（インターネット上での仕入れ・転売）で成果を出すためのコツを要点別に整理したものです。
1〜8章が「勝ち方」（リサーチ・仕入れ・販売の手順）、9〜10章が「負けない方法」
（失敗事例・規約/税務/資金繰りリスク・長期戦略）に対応しています。

## 1. 電脳せどりとは

- 店舗に足を運ばず、ネット上（Amazon・楽天市場・Yahoo!ショッピング・メルカリ・ヤフオクなど）で
  仕入れて別のプラットフォームで販売する手法。店舗せどりに比べて時間や場所の制約が少なく、
  リサーチツールを使えば効率的に利益商品を見つけやすいのが特徴。
- 参入者が増え価格差が縮小している商品も多く、以前より緻密なリサーチと利益計算が求められている。

## 2. 仕入れ先の選び方

- **楽天市場・Amazon・Yahoo!ショッピング**：大手ECモールは定番の仕入れ先。
  楽天スーパーセール／お買い物マラソン、Yahoo!ショッピングの「5のつく日」など
  大型セール・ポイント還元day を狙う「ポイントせどり」が有効。
- **メルカリ・ヤフオク**：個人出品が中心のため、相場より安い「掘り出し物」が見つかりやすい。
  ただし仕入れた商品は法律上「中古品」扱いになる点に注意（詳細は5章）。
- 初心者は価格差リサーチのしやすさ・発送スピードの観点から、まず国内の大手モールから始めるのが無難。

## 3. 商品選定・リサーチのコツ

- **新品からスタート**：検品が不要で仕入れたらそのまま出品でき、同一商品をまとめて集めやすいため、
  初心者は新品中心の仕入れが取り組みやすい。
- **利益計算を必ず行う**：「販売価格 − 仕入れ値 − 送料 − 各種手数料」で利益率を算出し、
  目安として利益率20〜30%以上を確保できる商品を選ぶ。
- **仕入れコストの圧縮**：ポイント還元・クーポン・まとめ買い割引を活用して実質仕入れ値を下げる。
- **需要と相場の見極め**：価格推移や売れ行きデータを見て仮説を立て、コツコツとリサーチを継続できる
  ことが電脳せどりで成果を出す人の共通点。
- 在庫リスクを踏まえた予算管理（仕入れすぎない、回転率を意識する）も重要。

## 4. あると便利なリサーチツール

| ツール | 特徴 |
|---|---|
| クイックショップ | Amazon商品ページに詳細情報を表示するGoogle拡張機能。手数料・ポイントを考慮した利益を自動計算 |
| 雷神 | Amazonと楽天（またはYahoo!ショッピング）の価格を比較し、利益商品を自動抽出する価格比較ツール |
| PoiPoiポケット | 楽天市場で仕入れてAmazonで販売する際の価格差商品を自動抽出 |

リサーチツールを導入することで、需要・相場の確認や利益計算の手間を大幅に削減できる。

## 5. 注意点・法律リスク

- **古物商許可**：一度でも一般消費者の手に渡った商品は、未開封の新品であっても法律上「中古品」となるため、
  メルカリ等の個人売買アプリから仕入れた商品を継続的に転売する場合は古物商許可が必要になるケースがある。
  無許可営業は古物営業法違反となり、3年以下の懲役または100万円以下の罰金の対象になり得る
  （一度取消を受けると5年間は再取得不可）。
- **プラットフォーム規約違反**：規約違反と判断されるとAmazon・メルカリ等のアカウント自体が
  停止されるリスクがある。各モールの出品ポリシーを事前に確認する。
- **転売禁止・権利侵害商品を避ける**：転売が禁止されている商品や、商標権・著作権など
  知的財産権を侵害するリスクのある商品（並行輸入品の扱いなど）は取り扱わない。

## 6. まとめ：向いている人の特徴

- 数字の分析やリサーチ作業をコツコツ続けられる
- 価格推移・需要データを見て仮説を立てるのが好き
- 在庫リスクを踏まえて予算管理ができる

これらの適性がある人ほど、電脳せどりで安定した成果を出しやすいとされる。

### 7-1. 仕入れ先選定系の動画から
- 仕入れ先を1つに絞らず、家電量販店系ネットショップ・アウトレットモール・メーカー公式通販・
  楽天/Yahoo!ショッピングの中小店舗などを並行してチェックすると値下がりタイミングを拾いやすい。
- 「仕入れ先ランキング」系の動画では、有名な大手モールだけでなく検索されにくい中小ネットショップを
  開拓することが、価格差を生む差別化ポイントとして繰り返し語られている。

### 7-2. リサーチ手法・ツール系の動画から
- **せどり三種の神器**：Keepa（Amazonの価格・ランキング推移グラフ）、楽天市場、Amazon本体の
  3つを併用して価格差を判断するのが基本形として紹介されることが多い。
- **Keepaは感覚でなく数字で仕入れ判断する道具**：過去の価格推移・出品者数の増減・ランキング変動を見て、
  一時的な値下がりか恒常的な相場下落かを見極める。
- **「全頭検索」系ツール（DELTAGIGAなど）**：楽天・Yahoo!ショッピングなど多数の店舗を自動巡回し、
  「90日平均価格」に対して「現在価格」が大きく下回っている商品を抽出する使い方が典型。
  モール別・カテゴリ別のフィルターを組み合わせることで独自性の高いリサーチができる。
- **基本リサーチ法は大きく2系統**：①Amazon側の売れ筋から逆算して安い仕入れ先を探す「Amazon起点」型、
  ②仕入れ先のセール・値下げ情報を起点にAmazon側の需要を確認する「仕入れ先起点」型に整理されることが多い。
- **「刈り取り」手法**：Keepaの価格トラッキング機能で目標価格をあらかじめ設定しておき、
  実際にその価格以下まで下落したタイミングで自動通知（アラート）を受け取ってから仕入れる、
  という能動的な仕入れテクニック。グラフを都度見に行く受動的な使い方より効率的とされる。
- **新品・中古・Amazon本体を分けて価格推移を追う**：Keepaのグラフは「新品」「中古」
  「Amazon本体（Amazonが自ら出品者になっているケース）」で価格ラインが分かれており、
  Amazon本体が出品中は価格競争に巻き込まれやすいため、このラインの有無を仕入れ判断に使う。
- **出品者急増→値崩れの波を予測する**：出品者数が急に増えたタイミングをランキング・出品者数
  グラフから捉え、その後に来やすい価格崩壊（値崩れ）の波を先読みして仕入れを見送ることで、
  不良在庫化を未然に防ぐ。単に「出品者数の増減を見る」より一歩踏み込んだリスク回避の視点。

### 7-3. 実践密着・体験談系の動画から
- 初心者がプロに同行・指導を受ける形式の動画では、「自己流で手法を転々とするより、
  教わった1つのリサーチの型を反復する」ことの重要性が共通して語られている。
- 店舗せどりから電脳せどりへ移行した事例では、リサーチ対象を「店舗の実在庫」から
  「ネット上の価格変動」に切り替えたことで、時間あたりの利益商品発見数が上がったという報告が多い。
- 日用品・消耗品カテゴリはリピート需要があり、副業で小さな利益を積み上げる入門ケースとして
  紹介されやすい。

### 7-4. 楽天ポイントせどり系の動画から
- **お買い物マラソン**：ショップ買い回り件数に応じて還元率が段階的に上がるため、
  「必ずエントリーする」「複数ショップに分散して買い回り件数を稼ぐ」のが鉄則。
- **「5と0のつく日」**：楽天カード決済が条件で還元倍率が上がるため、お買い物マラソンと
  併用して仕入れタイミングを合わせると還元率を最大化できる。
- **楽天スーパーDEAL**：15〜50%のポイント還元が付いた商品が対象になることが多く、
  通常のクーポン探しより見落とされがちな仕入れ元として狙い目。
- 利益商品公開系の動画では「仕入れ価格・販売価格・手数料・送料・ポイント還元後の実質粗利」を
  セットで開示するものが多く、同じ商品構造で類似品を探す練習材料になる。

### 7-5. 警鐘・注意喚起系の動画から
- ツールの初期設定や「王道」とされるリサーチ手法だけに依存し続けると、参入者が増えるほど
  価格差が消えやすいため、独自のフィルター・仮説を持つことが繰り返し推奨されている。
- 儲からなくなる典型パターンとして、①同じ商品ジャンルに固執する、②送料・手数料・値下がり
  リスクを見落として利益計算が甘くなる、③古物商許可やプラットフォーム規約を確認せず
  販路だけを広げる、の3点が挙げられている。

## 8. 具体的な仕入れ〜販売の実例（モデルケース）

> **注記**：以下はいずれも実在の商品・価格ではなく、これまでの章で挙げたノウハウ（Keepaでの
> リサーチ、楽天ポイントせどり、全頭検索ツールの使い方、利益率20〜30%の目安）を
> 組み合わせて再現した**架空のモデルケース**です。価格差は日々変動し縮小しやすいため、
> 実際に仕入れる際は必ず自分でリサーチツールを使って最新の相場を確認してください。
>
> **重要（2026年9月 追記）**：以下の例では販売手数料を一律15%、FBA手数料を固定値で
> 計算しているが、**これは説明用の簡略化であり、実際の判定に使ってはいけない**。
> Amazonの販売手数料はカテゴリーによって異なり（概ね5〜15.4%程度）、FBA配送代行手数料も
> サイズ・重量区分によって変わる。実際の仕入れ判定では、**ASIN単位でAmazonが無料提供している
> Revenue Calculator（FBA料金シミュレーター）の数値を使うこと**。なお同ツールにも
> 月額登録料・商品ごとの成約料・返送/所有権放棄手数料など含まれない費用がある点に注意。

### ケース1：Amazon起点型（日用消耗品／楽天ポイントせどり）

1. **Amazon側で先に「売れる商品」を確認**：Keepaで過去90日の価格推移・ランキングを見て、
   相場が4,800〜5,200円で安定し、出品者数が多すぎないことを確認。
2. **楽天市場で同一商品（JANコード一致）を探す**：通常価格2,980円（税込・送料無料店舗）。
3. **セールタイミングを合わせる**：「お買い物マラソン」（買い回り9店舗で+9%）＋「5と0のつく日」
   （楽天カード決済で+4%）＝還元率合計14%（実質417円分還元）。
4. **利益計算ツールで事前シミュレーション**：

   | 項目 | 金額 |
   |---|---|
   | Amazon販売価格 | 4,980円 |
   | Amazon販売手数料（約15%） | −747円 |
   | FBA配送代行手数料（目安） | −588円 |
   | 楽天仕入れ値（税込） | −2,980円 |
   | 楽天ポイント還元（実質＋） | +417円 |
   | **粗利／利益率** | **1,082円（約21.7%）** |

5. **仕入れ→FBA納品→販売**：新品のため検品不要。納品プラン作成→ラベル貼付→倉庫へ発送→
   注文が入ると自動出荷→売上は概ね2週間ごとに入金。
   月30個売れれば粗利約32,460円（副業レベルの積み上げ例）。

### ケース2：仕入れ先起点型（楽天スーパーDEAL活用）

1. **仕入れ先のセール情報が起点**：楽天スーパーDEAL対象の調理器具アクセサリー
   （例：圧力鍋用パッキン3個セット）が30%ポイント還元中と発見。
2. **Amazon側の需要を後追いで確認**：Keepaで相場が5,000円台前半で安定していることを確認してから仕入れ判断。
3. **利益計算**：

   | 項目 | 金額 |
   |---|---|
   | Amazon販売価格 | 5,480円 |
   | Amazon販売手数料（約15%） | −822円 |
   | FBA配送代行手数料（目安） | −650円 |
   | 楽天仕入れ値（定価・税込） | −3,480円 |
   | 楽天スーパーDEALポイント還元（30%） | +1,044円 |
   | **粗利／利益率** | **1,572円（約28.7%）** |

4. **ポイント**：スーパーDEAL対象商品は通常のクーポン探しより見落とされがちなため、
   専用ページを定期的に巡回するのが鉄則。

### ケース3：中古品ルート（メルカリ仕入れ→ヤフオク販売）

1. **仕入れ**：メルカリで型落ちの美容家電（ヘアアイロン）を送料込み4,000円で購入。
   一般消費者の手を経由した時点で法律上「中古品」扱いになる点に注意。
2. **義務事項**：継続的に行う場合は古物商許可を取得し、仕入れごとに古物台帳へ
   商品情報・相手方の記録を残す。
3. **販売**：ヤフオクに出品、7,000円で落札。

   | 項目 | 金額 |
   |---|---|
   | 販売価格 | 7,000円 |
   | 販売手数料（約10%） | −700円 |
   | 発送送料（販売者負担分） | −700円 |
   | メルカリ仕入れ値（送料込み） | −4,000円 |
   | **粗利／利益率** | **1,600円（約22.9%）** |

4. **注意**：新品ルートと違って検品・清掃・付属品確認の手間が発生する。無許可営業は
   古物営業法違反（3年以下の懲役または100万円以下の罰金）のリスクがあるため必須対応。

### ケース4：ツール活用型（全頭検索ツールで見つけた特価処分品）

1. **リサーチ**：DELTAGIGAのようなツールで「90日平均価格12,000円」に対し
   「現在価格6,000円」（50%オフ）まで下がった型落ち調理家電を検出。
2. **需要確認**：Keepaで、セール終了後は相場が11,000円前後に戻る傾向があることを確認。
3. **利益計算**：

   | 項目 | 金額 |
   |---|---|
   | Amazon想定販売価格（相場回復後） | 11,000円 |
   | Amazon販売手数料（約15%） | −1,650円 |
   | FBA配送代行手数料（目安） | −750円 |
   | 仕入れ値（特価） | −6,000円 |
   | **粗利／利益率** | **2,600円（約23.6%）** |

4. **ポイント**：一時的な特価品は在庫に限りがあるため、複数店舗をツールで横断的に
   監視し、見つけ次第まとめて仕入れる機動力が利益の再現性を左右する。

## 9. 勝率を上げるための「負け筋」対策（失敗事例・リスク管理）

利益商品の見つけ方（勝ち方）だけでは勝率は上がらない。実際に退場者を生んでいるのは
以下の領域であり、ここを潰すことが期待値を底上げする最短ルートになる。

### 9-1. 退場理由の典型パターン
- **不良在庫による赤字**：流行り廃りのある商品で在庫が徐々に積み上がり、売れ残って赤字化する
  ケースが最も多い。
- **価格競争・値崩れ**：店舗やネットで「山積みの在庫処分品」は、ライバルも同じものを仕入れて
  いる可能性が高く、出品者が増えて値下げ合戦になりやすい。
- **利益と作業量のギャップ**：最大の離脱要因。時間あたりの利益（時給換算）を計測しないまま
  作業量だけが膨らむと続かない。
- **アカウント停止**：販売先の規約違反で売り場そのものを失う。
- **自己管理の破綻**：在庫・資金・納期の管理が甘いと、利益が出ていても回らなくなる。

### 9-2. Amazon真贋調査（最大の地雷）
- 購入者の申告やメーカーからの申し立てをきっかけに調査が入り、正規品であることを証明できないと
  アカウント閉鎖に至る可能性がある。
- **求められる書類は「請求書」**（領収書では不十分なことが多い）。要件は概ね次の通り：
  - 発行日が仕入れ時期と一致している
  - 仕入れ先（正規卸・メーカー）の社名・住所・連絡先が明記されている
  - 品番・ASINが出品商品と一致している
  - 数量・金額が出品数量と整合している
  - PDF/画像で鮮明に読み取れる
- **電脳せどりは構造的に不利**：小売店から購入するため上記要件を満たす請求書が出ないことが多く、
  調査突破の難易度が高い。メーカー仕入れの方がリスク面では有利。
- **最大の対策は「来てから対処」ではなく「来ないように立ち回る」**：メーカーが権利行使に積極的な
  ブランド・ジャンルを仕入れ対象から外す。リスク商品を判定するツール（セラースケット等）もある。

### 9-3. アカウント健全性を数値で管理する
- Amazonの健全性は5指標で評価される：①注文不良率（ODR）②出荷前キャンセル率③出荷遅延率
  ④追跡可能率⑤規約の順守。
- **ODRは1%未満が基準**。超えると警告 → 出品制限 → アカウント停止へと進む。
- ODR悪化の主因は「商品説明と実物の乖離」「不良品の発送」「対応の遅さ」。中古品を扱う場合は
  コンディション表記を厳しめに書くのが結果的に防御になる。

### 9-4. 仕入れ側プラットフォームの規約リスク（楽天の例）

> **2026年9月 訂正**：当初この節には「楽天市場は転売目的の購入を禁止している」と記載していたが、
> 包括的な禁止と断定するのは不正確だった。再調査の結果を以下に整理する。

**正確な整理**
- 楽天市場全体として「転売目的の購入」を包括的に禁止しているとまでは言えない。
- ただし**転売禁止の規程が及ぶ商材がある**：契約等で譲渡・転売が禁止されている商材、
  メーカーが転売禁止を公表している商品（流通経路がメーカー直販のみのもの）を
  一般消費者向け販売店から購入したもの。
- **買い占め等が「不適切利用」と判断されると、アカウントロックや注文キャンセルの対象になり得る**
  （楽天市場の安心・安全ページに明記）。
- **最も明確なのは楽天カードの規約**：2022年6月21日の改定で、
  **せどり・転売仕入れを目的とした楽天カードの使用が明確に禁止された。**
- 各ショップ独自の販売条件・数量制限・キャンペーン条件も別途遵守する必要がある。

**この計画にとっての重大な含意**
11章で推奨している「楽天ポイントせどり」は、**5と0のつく日のポイント倍率条件として
楽天カード決済を前提にしている**。しかし上記の通り、楽天カード規約はせどり仕入れ目的の
使用を明確に禁止している。つまり**手法の中核部分が規約と正面から衝突している**。
- 対策は「バレない程度に買う」ではなく、**この手法を採用するかどうかの判断そのもの**である。
- 楽天カードのポイント倍率を前提から外すと、モデルケースの還元率14%は大きく下がり、
  利益設計が成立しなくなる可能性がある。
- 採用する場合は、最新の楽天カード会員規約を自分で確認した上で、リスクを認識して判断すること。

**実務家はどう対応しているか（2026年9月調査）**

コミュニティはすでに「楽天カードNG後」を前提に動き始めている。
2026年版で「せどり・物販の仕入れカード比較｜**楽天NG後の選び方**」という記事が出ており、
タイトル自体が実態を示している。対応は概ね3パターンに分かれる。

| パターン | 内容 | 評価 |
|---|---|---|
| (A) 他社カードへ移行 | 楽天カードを使わず別のカードで仕入れる | 規約上クリーン。**推奨** |
| (B) 楽天ビジネスカードへ切替 | 商用利用OKのカード。ただし申込には楽天プレミアムカードの保有／同時申込が必要で年会費が発生 | 筋は通るが、月3万円規模では年会費が13-4の固定費ロジックに引っかかる |
| (C) 個人カードのまま継続 | 人数としてはおそらく最多 | **規約違反状態を抱え続ける。非推奨** |

**楽天側が転売を疑う特徴**
- 繰り上げ返済を何度も行う（資金回転を速くするせどり特有の動き）
- 購入商品の自動キャンセルが相次ぐ

指摘された場合は、カード利用停止＋楽天会員アカウント停止＋**獲得ポイント全額没収**。
強制解約されると**再契約はできない**。

**代替手段でポイント倍率は取れるか → 部分的に不可**
- **「5と0のつく日」は楽天カード決済が必須条件**。楽天キャッシュ・銀行振込・他社クレジットカードは
  すべて対象外。規約を守る場合、この+4%は諦めるしかない。
- **お買い物マラソンの買い回り（+9%）は決済手段を問わない**ため、こちらは維持できる。

**数字への影響（8章ケース1の再計算）**

| | 還元率 | 実質還元額 | 粗利 |
|---|---|---|---|
| 楽天カードあり | 14% | 417円 | 1,082円 |
| **楽天カードなし** | **約10%** | **298円** | **963円** |

粗利は約11%減。**963円は11-3の仕入れ基準「粗利1,000円以上」をわずかに下回る**。
手法が成立しなくなるわけではないが、**基準を満たす商品の母数はさらに減る**。
これはPhase 0（15-4）の通過率に直接影響する。

**結論：現実的な選択肢は2つ**
1. **他社カードで、お買い物マラソン中心に組む**（+9%は確保できる）
2. **楽天ポイントせどりを主軸から外す** — Yahoo!ショッピングなど他モール起点に切り替える

いずれにせよ、**Phase 0の机上リサーチは「楽天カードなし・還元率10%前提」で通過率を測るべき**。
そこで十分な件数が残れば手法として成立し、残らなければ楽天起点そのものを見直す判断材料になる。

> **決定事項（2026年9月22日）**：規約上使えないものは使わない方針とし、**楽天カードは
> 仕入れに使わない**ことを決定。楽天市場での仕入れ自体は継続し、決済は**他社の
> クレジットカードに切り替える**（選択肢1を採用）。「5と0のつく日」の+4%は放棄し、
> お買い物マラソンの買い回り+9%のみを狙う。還元率は引き続き**約10%前提**で計算する
> （楽天ビジネスカードは月3万円規模では年会費が見合わないため見送り）。
> 残タスク：仕入れ用の他社クレジットカードを用意する。
- 措置は**カード利用停止＋楽天会員アカウント停止＋獲得ポイントの凍結（全額没収）**に及びうる。
- 楽天は各種サービスが共通アカウントで紐づいているため、関連サービスすべてを一度に失う可能性がある。
- → ポイントせどりは「還元率が高い＝おいしい」だけで判断せず、**仕入れ口そのものを失うリスク**と
  セットで評価する。販売先だけでなく仕入れ先の規約も読む。

### 9-5. 資金繰り（黒字倒産を防ぐ）
- 重要なのは「現金力」より **「資金繰り管理能力」**。
- クレジットカード仕入れは翌月末払いまで繰り延べできるが、**1ヶ月以内に売れなければ売上入金より
  カード支払いが先に来る**。延滞すると1〜5年の信用情報事故につながり、多重債務に陥った実例もある。
- 設計の原則：**入金日が支払日より先に来るようにする**。締め日の異なるカードを組み合わせると、
  月末付近の仕入れで支払いを約1ヶ月延ばせる。
- 利益が出ていても在庫に化けていれば現金はない。月次で「在庫金額」と「手元現金」を分けて管理する。

### 9-6. 見落としやすいコスト
- **FBA在庫保管手数料**に加え、長期保管（271日以上）には**長期在庫追加手数料**が発生する。
- 2026年4月の改定では、**365日超の在庫に1点あたり月額20円の最低手数料が新設**され、
  低単価商品を大量に保管する出品者への影響が大きい。
- 返送にも所有権の放棄（処分）にも手数料がかかる。ただし長期在庫追加手数料より安いことが多いので、
  抱え続けるより早めに損切りする方が安く済むケースがある。
- → 利益計算には「売れ残った場合の保管・処分コスト」まで織り込む。回転率は利益率と同じくらい重要。

### 9-7. 税務（初心者が最も誤解する点）
- **在庫は経費ではなく「資産」**。仕入れた時点では経費にならず、売れて初めて売上原価になる。
- 年末に棚卸しを行い、期末在庫を差し引いて売上原価を計算する。
- そのため**在庫を大量に抱えたまま年を越すと、現金がないのに帳簿上の利益が出て課税される**という
  事態が起きる。年末の仕入れ量と在庫消化はセットで計画する。
- 青色申告には「開業届」と「青色申告承認申請書」を税務署へ事前提出し、承認を得る必要がある。
- 業種区分はインターネットを利用した「通信販売小売業」が基本。

### 9-8. カテゴリ別の許認可（扱う前に確認）
| ジャンル | 必要な許可・注意点 |
|---|---|
| 中古品全般 | 古物商許可（5章参照）。古物台帳への記帳義務あり |
| 医薬品 | 薬剤師または登録販売者の資格がなければネット販売も不可 |
| 電気用品 | PSEマークのない製品の販売自体が電気用品安全法違反（1年以下の懲役または100万円以下の罰金）。ただし中古販売事業者が買い取った中古品は、PSEマークを新規取得せずそのまま販売できる特例がある |
| 酒類・食品 | 別途、酒類販売免許や食品衛生法上の許可が必要 |

## 10. 長期的に勝率を上げる出口戦略

- せどりは**毎回市場で商品を探し続けなければならず、出品者が増えるほど値下げ競争が起きる**という
  構造的な弱点を抱えている。リサーチ力を磨いても、この構造自体は変わらない。
- **メーカー・卸仕入れへの移行**が王道の出口：
  - 一度契約すればリピート仕入れが可能になり、以降はメールや電話一本で継続的に仕入れられる
  - 出品者を絞る契約を結べるケースもあり、価格が比較的安定する
  - 真贋調査で求められる正規の請求書が出るため、9-2のリスクが構造的に下がる
  - メーカーとの取引関係そのものが資産として積み上がる
- **自動化・仕組み化で時間あたり利益を上げる**：
  - 価格改定ツール（プライスター等）で他出品者の価格変更に自動追従し、値下げ対応の張り付きを解消
  - FBA納品代行・梱包資材調達などの外注サービスを使い、リサーチと仕入れ判断に時間を集中させる
- 考え方の軸：**「利益額」ではなく「時間あたり利益 × 継続可能性」で手法を選ぶ**。
  9-1の最大の離脱要因が「利益と作業量のギャップ」である以上、勝率とは再現性と継続性のことである。

## 11. 月3万円を達成するための実行手順（0→1のロードマップ）

本章は1〜10章の内容を「副業で月数万円」という具体的な目標に逆算して並べ直したもの。
数値はモデルケース（8章）に基づく目安であり、実際の相場は必ず自分で確認すること。

### 11-0. 目標から逆算した設計

| 項目 | 目安 |
|---|---|
| 月間目標粗利 | 30,000円 |
| 1商品あたり粗利 | 1,500円（利益率20〜30%） |
| 必要販売個数 | 月20個（週5個） |
| 平均仕入れ単価 | 3,000円前後 |
| 月間仕入れ総額 | 約60,000円 |
| 必要運転資金 | 10〜12万円（仕入れと入金の重なりを考慮） |
| 想定作業時間 | リサーチ週3〜5時間＋納品作業 月2〜3時間 |

月5万円を狙う場合は同じ型のまま個数を30〜35個に増やす。**単価を上げるより個数を増やす方が、
検証済みの型を崩さずに済むため再現性が高い。**

### 11-1. 準備フェーズ（最初の1週間でやること）
1. **Amazon出品用アカウントを開設**：月49個未満の販売なら小口、それ以上なら大口（月額登録料が
   かかるため、月20個スタートならまず小口で十分）。
2. **Keepaを導入**：価格・ランキング・出品者数の推移グラフを見るための必須ツール。
3. **楽天会員＋楽天カードを用意**：ポイント還元の倍率条件（カード決済）を満たすため。
4. **開業届と青色申告承認申請書を提出**（9-7）。業種は「通信販売小売業」。
5. **古物商許可**：中古を扱う予定なら取得。新品のみで始めるなら後回しでよい（5章）。
6. **仕入れ専用のクレジットカードと口座を分ける**：資金繰りを可視化するため（9-5）。
7. **利益計算シートを作る**：「販売価格 − 仕入れ値 − 販売手数料 − FBA手数料 − 送料 ＋ ポイント還元」を
   入力するだけで粗利と利益率が出る形にする。

### 11-2. 型を1つに絞る（最重要）
- **推奨の型：楽天ポイントせどり × Amazon FBA**。理由は、セール日程があらかじめ決まっていて
  ルーティン化しやすく、ポイント還元という「確定した値引き」で利益を作れるため（7-4）。
- **ジャンルは日用品・消耗品に絞る**。リピート需要があり回転が速く、真贋調査リスクの高い
  有名ブランド品を避けられる（7-3／9-2）。
- 7-3の通り、**手法を転々とさせず1つの型を反復する**ことが最短ルート。

### 11-3. リサーチのルーティン（月2回のセール日に合わせる）
1. 楽天の「お買い物マラソン」「5と0のつく日」の日程を月初にカレンダー登録する。
2. セール前日までに候補をリストアップ（スーパーDEALの高還元商品も巡回）。
3. 候補ごとにKeepaで以下を確認する：
   - **90日平均価格 vs 現在価格**：一時的な値下がりか、恒常的な相場下落かを判別
   - **ランキング推移**：月に何個売れているか（回転の速さ）
   - **出品者数の推移**：急増していれば値崩れの波が来るため見送る（9-3）
   - **Amazon本体の出品有無**：出品中なら価格競争に巻き込まれやすいので避ける
4. 利益計算シートに入れて、**仕入れ基準を満たすものだけ**を残す。

**仕入れ基準（初心者向けの初期設定）**
- 利益率20%以上 かつ 粗利1,000円以上
- 月3個以上売れている実績がある（回転）
- 出品者数が急増していない
- Amazon本体が出品していない
- 有名ブランド品ではない

### 11-4. 仕入れフェーズ
1. **必ずテスト仕入れから**：新規商品は1回あたり2〜3個まで。いきなりロットで買わない（9-1）。
2. 買い回り件数を稼ぐため、複数ショップに分けてカートを構成する（7-4）。
3. **請求書・領収書は必ず保存**する。PDFで月別フォルダに整理しておく（9-2の真贋調査対策）。
4. **支払日より入金日が先に来るか**を確認してから決済する（9-5）。

### 11-5. 納品・販売フェーズ
1. 到着したら新品でも外装の破損・型番違いを確認する（ODR悪化を防ぐ／9-3）。
2. FBA納品プランを作成 → 商品ラベル貼付 → 梱包 → Amazon倉庫へ発送。
3. 価格改定ツールを使う場合は、**必ず赤字にならない下限価格を設定**してから自動追従させる。
4. 注文が入れば自動出荷。売上は概ね2週間ごとに入金される。

### 11-6. 在庫・撤退ルール（利益を守る工程）
1. **30日で動かない商品は値下げ検討、60日で損切り判断**。長期在庫追加手数料が発生する前に
   決着をつける（9-6）。
2. 月末に棚卸しを行い、「在庫金額」と「手元現金」を分けて記録する。
3. **年末は在庫を意図的に減らす**。在庫は資産であり、抱えたまま年を越すと現金がないのに
   課税される（9-7）。

### 11-7. 月3万円を安定させたあとの伸ばし方
1. まず**同じ型のまま個数を増やす**（20個 → 35個で月5万円）。
2. 次に**外注化**（FBA納品代行など）で自分の時間をリサーチと仕入れ判断に集中させる（10章）。
3. 最終的には**メーカー・卸仕入れへ移行**し、リピート仕入れと正規請求書によって
   価格競争リスクと真贋調査リスクを構造的に下げる（10章）。

### 11-8. 勝率を落とす「やってはいけないこと」チェックリスト
- [ ] 有名ブランド品を仕入れる（真贋調査リスク／9-2）
- [ ] テスト仕入れを飛ばして最初から大量ロットで買う（不良在庫／9-1）
- [ ] カードの支払日より入金日が後になる仕入れをする（黒字倒産／9-5）
- [ ] 年末に在庫を大量に抱えたまま越年する（課税／9-7）
- [ ] 楽天などで買い占めに見える購入をする（仕入れ口を失う／9-4）
- [ ] 利益率だけ見て回転率を見ない（保管手数料と資金拘束／9-6）
- [ ] 手法を次々に変えて、どれも検証が終わらない（7-3）

## 12. AI・ツールで代替できる工程／できない工程

### 12-1. まず担当領域を混同しない

| 種別 | 代表例 | 担当する工程 |
|---|---|---|
| **リサーチ系ツール** | Keepa、DELTAGIGA、雷神、せどりすと | 価格・ランキング・出品者数の取得と監視、価格差商品の抽出 |
| **販売運用系ツール** | プライスター | **リサーチではない**。価格の自動改定、商品登録〜納品の簡略化、売上・在庫管理、サンクスメールの自動送信（月額5,280円／初回30日無料） |
| **生成AI** | ChatGPT、Claude | 情報の要約・構造化・計算・文章生成・仮説出し |

**よくある誤解**：プライスターを「リサーチが自動化できるツール」と捉えると期待外れになる。
これは売れた後の運用コストを下げるツールであり、仕入れ判断には関与しない。

### 12-2. 生成AIが「使える」部分

- **レビューの要約によるリスク検知**：購入者レビューを貼り付けて「悪い評価やクレームの内容を
  要約して」と指示すると、不良品率やサイズ違いなどの地雷を仕入れ前に把握でき、失敗率を下げられる。
  ODR悪化（9-3）の予防にも直結する、費用対効果が最も高い使い方。
- **利益計算とシート設計**：手数料・送料・ポイント還元を含む計算式の設計、計算の検算、
  スプレッドシートの数式作成。
- **仕入れ基準のチェックリスト化**：11-3の基準をプロンプト化し、候補商品の情報を貼って
  「この基準を満たすか順に判定して」と使う（判断材料の整理であり、判断そのものではない）。
- **仮説出し**：季節性やカテゴリの当たりをつける、リサーチの切り口を広げる。
- **文章作成**：商品説明文、サンクスメール文面、真贋調査時の業務改善計画書のドラフト。
- **定型作業の圧縮**：出品情報の整形、商品説明の要約など、ルーチンの時短。
- 2026年時点では「情報収集 → 要約 → 構造化 → 共有」の4工程はAIエージェントやZapier等と
  組み合わせて**半自動化**が現実的なレベルに達している。

### 12-3. 生成AIが「使えない」部分（ここを任せると事故る）

- **チャット型のAI単体はリアルタイムの相場・在庫データを持っていない**。「利益商品を探して」と
  指示しても正しい現在価格は出せず、**もっともらしい嘘（ハルシネーション）を返す**。
  価格データの取得は必ずKeepa等の一次ソースで行い、AIには「取得済みデータの解釈」だけをさせる。
  （※PC操作・ブラウジングができるエージェント型AIでは事情が変わる。12-5を参照）
- **最終的な仕入れ判断**：回転・競合・資金状況を踏まえた意思決定と、そのリスクは人間が負う。
- **規約・法令の最終確認**：楽天やAmazonの規約、古物営業法、PSE法などは改定される。
  AIの知識は古い可能性があるため、必ず公式の一次情報を確認する（9-4／9-8）。
- **真贋リスクの最終判定**：そのブランドが権利行使に積極的かどうかは、AIの推測ではなく
  実際の出品者コミュニティの情報と自分の経験で判断する（9-2）。
- **資金繰りの実行管理**：カードの締め日・入金日の実データ管理は人間の責任範囲（9-5）。
- **現物の検品**：外装破損、型番違い、付属品欠品の確認は代替できない。

### 12-4. 11章の工程別・担当マトリクス

| 工程 | 専用ツール | 生成AI | 人間 |
|---|---|---|---|
| 候補商品の抽出 | ◎ 全頭検索で自動抽出 | × 相場を持たない | △ 切り口の設定 |
| 価格・ランキング取得 | ◎ Keepaが一次ソース | × | － |
| グラフの解釈 | △ 表示まで | ◯ 貼り付ければ解釈可能 | ◎ 最終判断 |
| レビューのリスク分析 | × | ◎ 要約が得意 | △ 確認 |
| 利益計算 | ◯ 自動計算機能あり | ◎ 式の設計・検算 | ◎ 基準の決定 |
| 仕入れ判断 | × | × | ◎ 人間のみ |
| 規約・法令確認 | × | △ 論点整理まで | ◎ 一次情報で確認 |
| 出品・納品作業 | ◎ プライスター等 | ◯ 文章作成 | △ 検品 |

| 在庫・撤退判断 | ◯ データ提示 | ◯ 整理・可視化 | ◎ 損切り決断 |

### 12-5. エージェント型AI（GPT-6 Astra等）はリサーチに使えるか

2026年9月に発表されたGPT-6 Astraのように、**PC画面を見ながらマウスとキーボードを操作し、
ブラウザを自律的に動かせるモデル**が登場した。これにより「AIはリアルタイム価格を取得できない」
という技術的制約は、原理上は解消されている。ただし**実務で使えるかは別問題**で、
ボトルネックは「AIの能力」から「プラットフォームの規約」に移った。

**技術的にできること**
- フォーム入力、ページ遷移、リンククリックなど画面操作を伴う作業の代行
- 「調べる → 要約する → ファイルを作る」を1タスクとして通しで実行
- 推論の深さを5段階（low〜max）で調整可能、コンテキストは約105万トークン

**コスト面の制約**
- API料金は入力100万トークンあたり$10、出力100万トークンあたり$50（前世代の2.5倍）。
  毎日大量の商品を回すリサーチ用途では、ツール月額数千円と比べて割高になりやすい。
- ChatGPTのプランにも利用上限がある（例：Pro $100プランのチャットは週50メッセージ）。

**そして最大の落とし穴：規約リスクが自分のアカウントに跳ね返る**
- **Amazonは自動化ソフトウェアやAIエージェントがサービスへアクセスする際の要件を追加している。**
  エージェントに自動巡回させると、アクセス拒否やCAPTCHAが発生するだけでなく、
  **その結果は自分のIPアドレスと自分のAmazonアカウントに跳ね返る**。
- **楽天市場では、店舗ページや商品一覧を自動収集する行為は商用利用とみなされ厳しく制限されている。**
  過去には無断取得による警告やサービス停止の例もある。
- つまり、**9-4で挙げた「仕入れ口・売り場を失う」という最悪の失敗モードを、
  自分でAIに踏ませることになりかねない**。効率化のつもりが最大のリスクを取る行為になる。
- 公式ルートはAmazonのSP-API（用途・データ保護・保管期間などポリシー遵守が前提）や、
  Keepaなど各ツールが提供する正規のAPI。

**安全な使い方の設計**
1. **データ取得は正規ルートに限定する**：Keepa等のツール、または公式API。
   エージェントにECサイトを自動巡回させない。
2. **取得したデータをAstraに渡して分析させる**：この使い方なら規約リスクなしで
   エージェント型AIの推論能力を活かせる。
3. **判断と責任は人間が持つ**：12-3の「使えない部分」はエージェント型でも変わらない。

> **実例（2026年9月22日）**：Phase 0バッチ2でGPT-6 Astraに10件の商品調査を依頼したところ、
> 楽天側は問題なく完了した一方、**Amazon側は「ブラウザが拒否され」、価格・出品者情報を
> 一切取得できなかった**。上記の懸念が実際に発生した形だが、Astra自身が標準料率などで
> 数字を捏造せず、空欄のまま正直に報告してきたため、実害はなく安全に停止した。
> 教訓として、**Amazon側のデータ収集はエージェントに任せず、人間が通常のブラウジングで
> 行う**運用に切り替えた（詳細は`docs/phase0-kit/research-log/README.md`参照）。

### 12-6. 結論：「半自動」が正解

AIがブラウザを操作できるようになっても、結論は変わらない。完全自動化を目指すと、
ハルシネーションと規約違反の両方でリスクが跳ね上がる。
**データ取得は専用ツール（正規ルート）、整理と要約は生成AI、判断と責任は人間**という
三層に分け、最終判断と一次情報の確認だけは必ず人間が握る設計にすること。
**技術的に可能になったことと、やっていいことは別**である。

## 13. 工数と収益の試算（ツール・AI併用モデル）

12章の「使えるところはツール・AI、残りは人力を最小化」という方針で運用した場合の試算。
数値は11章の設計（粗利1,500円／個）とツールの一般的な機能をもとにしたモデルであり、
実際の相場・料金は必ず自分で確認すること。

### 13-1. 工程別の月間工数（月20個＝粗利3万円のケース）

| 工程 | 手作業のみ | ツール・AI併用 | 削減の主因 |
|---|---|---|---|
| セール日程の把握・計画 | 1h | **0.5h** | カレンダー化、AIに整理させる |
| 候補商品の抽出 | 10h以上 | **2〜3h** | 全頭検索ツールが自動巡回、人は結果確認のみ |
| Keepa精査（候補40〜60件） | 4h | **3〜4h** | ほぼ削減できない中核工程 |
| 利益計算 | 2h | **0.5h** | 計算シート・ツールの自動計算 |
| レビューのリスク確認 | 2h | **0.5h** | AIに要約させる |
| 発注作業（買い回り構成・決済） | 1.5h | **1〜1.5h** | 削減困難（規約上、自動化は不可） |
| 検品・納品（20個） | 3h | **2〜3h** | 物理作業のため削減困難 |
| 価格改定 | 3h | **0.5h** | 価格改定ツールが自動追従、確認のみ |
| 在庫・撤退判断 | 1h | **0.5h** | データ提示は自動、判断は人間 |
| 帳簿・記録 | 2h | **1h** | AIで整形 |
| **合計** | **約30h** | **約12〜15h** | 概ね半減 |

**ポイント**：削減できるのは「探す・集計する・整形する」工程。
**削減できないのは「判断する・現物を扱う・決済する」工程**で、ここが人力の下限になる。

### 13-2. 規模別シナリオ

| 規模 | 月間粗利 | 販売個数 | 月間工数 | 時給換算 | 必要運転資金 |
|---|---|---|---|---|---|
| 入門 | 30,000円 | 20個 | 12〜15h（週3h強） | 約2,000〜2,500円 | 10〜12万円 |
| 副業安定 | 50,000円 | 約35個 | 18〜22h（週5h） | 約2,300〜2,800円 | 15〜20万円 |
| 副業上限 | 100,000円 | 約65個 | 30〜35h（週8h） | 約3,000円 | 30〜40万円 |

**月10万円が自力運用の分岐点**：この規模になると検品・納品の物理作業だけで月10時間近くになる。
ここからはFBA納品代行などの外注に切り出さないと工数が頭打ちになる（10章）。
外注費は粗利から引かれるため、**「時給を買う」判断として捉える**。

### 13-3. 立ち上げ期の現実（最初の3ヶ月）

| 時期 | 追加工数 | 想定収益 | 内容 |
|---|---|---|---|
| 初月 | +10〜15h | ほぼゼロ〜赤字 | アカウント開設、ツール設定、開業届、基準づくり、テスト仕入れ |
| 2ヶ月目 | +5h | 1〜2万円 | 基準の微調整、初回の販売と入金サイクルの確認 |
| 3ヶ月目 | 通常運用 | 2〜3万円 | 型が固まり、13-1の工数に収束 |

**初月から3万円は出ない**という前提で始めること。
9-1の最大の離脱要因が「利益と作業量のギャップ」である以上、
立ち上げ期の工数を織り込まずに始めると、ほぼ確実に途中で止まる。

### 13-4. ツール固定費の落とし穴（重要）

- 価格改定ツールは月額5,280円程度（プライスターの例）、これにKeepaの有料プラン、
  全頭検索系ツールを足すと**月1万円前後の固定費**になりうる。
- **月3万円の粗利に対して固定費1万円は重い**。手残りは2万円になり、時給換算は一気に下がる。
- したがって**導入順序が重要**：
  1. **最初はKeepaだけ**で始める（リサーチの中核であり、これがないと判断ができない）
  2. 月20〜30個が安定してきたら**全頭検索系ツール**を追加（候補抽出の工数削減が固定費を上回る）
  3. 出品数が増えて価格追従が負担になったら**価格改定ツール**を追加
- 判断基準は常に「**そのツールが削減する工数 × 自分の時給 > 月額料金**」かどうか。

### 13-5. 結論

- **月3万円なら週3時間強（月12〜15時間）、時給換算2,000〜2,500円**が現実的な目安。
- ツール・AI併用で工数は**概ね半減**するが、**判断・現物・決済の工程は残る**ため、
  ゼロにはならない。
- 収益を伸ばす順序は「**個数を増やす → 外注化 → メーカー仕入れへ移行**」（10章）。
- 固定費は先に払わず、**工数削減効果が料金を上回った時点で段階的に導入する**。

## 14. ツール詳細と「自作」の検討

### 14-1. 主要ツールの役割

| ツール | 種別 | 機能 | 料金 |
|---|---|---|---|
| クイックショップ | Chrome拡張 | Amazon商品ページに詳細情報を重ねて表示し、手数料・ポイントを考慮した利益を自動計算 | 要確認 |
| 雷神 | 価格比較 | Amazonと楽天（またはYahoo!ショッピング）の価格を比較し、利益が出そうな商品を自動抽出 | 要確認 |
| PoiPoiポケット | 価格比較 | 楽天仕入れ→Amazon販売に特化して価格差商品を自動抽出 | 要確認 |
| DELTAGIGA | 全頭検索 | 仕入れ先31店舗に対応し24時間365日巡回。「90日平均価格1万円／現在価格6千円」のようなフィルタで一時的な特価品を抽出 | 要確認 |
| セラースケット | リスク判定 | 真贋調査・アカウント停止につながりやすい危険商品を事前に判定（9-2の予防） | 要確認 |
| プライスター | 販売運用 | 価格自動改定、在庫・売上管理、サンクスメール自動送信。納品代行の仲介や梱包資材販売も併設 | **月5,280円**（初回30日無料） |

料金が「要確認」のものは本ドキュメント作成時点で未確認。導入前に公式サイトで確認すること。

### 14-2. Keepaの自作は現実的でない

障害はロジックではなく**データ**にある。
- Keepaの価値は**何年分もの価格・ランキング履歴の蓄積**であり、今日から作り始めても過去履歴は
  手に入らない。
- 収集元はAmazonであり、スクレイピングは規約違反リスクが自分のIP・アカウントに跳ね返る（12-5）。
- 正規のPA-APIは売上実績がないと実質使えずレート制限も厳しい。SP-APIは自分のセラーアカウントの
  データが中心。
- 結果として現実解は「**Keepa APIを有料で利用して自分用のツールを作る**」であり、
  これはKeepaの自作ではなく「Keepaのデータを使った自作」である。

### 14-3. 自作価値が高い領域

1. **自分の仕入れ基準の判定ロジック**：11-3の基準（利益率20%以上／粗利1,000円以上／
   月3個以上／出品者急増なし／Amazon本体不在）をコード化し、Keepa APIのデータに適用する。
   実質的に全頭検索ツールの代替に近いものが作れる。
2. **資金繰り管理ツール**：カードの締め日・支払日と入金予定を突き合わせる（9-5）。
   既製品がほぼ無い領域であり、かつ最も事故が起きやすい工程。
3. **利益計算スクリプト**：手数料率やポイント還元の条件は自分の取引条件に合わせるべきなので
   むしろ自作推奨。
4. **仕入れ記録・請求書の自動整理**（9-2の真贋調査対策）
5. **棚卸・売上原価の集計**（9-7の確定申告対応）

### 14-4. 価格改定ツールの自作は十分に現実的

**サーバーは障害にならない。**
- SKU数20〜65個（13章の規模）では負荷は極小で、**ローカルPCのcron／タスクスケジューラで足りる**。
  ラズパイでも動く。
- PCが停止している間は動かないが、月20個＝1日1個も売れない規模では、価格改定が数時間遅れても
  実害はほとんどない。
- 常時稼働が必要なら月数百円のVPS、またはGitHub Actionsのスケジュール実行でも組める。
- SP-APIのレート制限もこの規模では問題にならない。

**実際の障壁は次の2つ。**
1. **SP-APIのオンボーディング**：開発者登録 → Seller Centralでのアプリ作成 → LWAのOAuthフロー →
   リフレッシュトークン管理 → 必要なロールの権限申請。数時間ではなく数日かかる作業。
2. **事故時の損害**：バグによる1円出品や底値への追従は、月額5,280円より遥かに高くつく。

**必須の安全装置**
- **ハード下限価格**：原価＋手数料を割る価格には絶対に改定しない
- **1回あたりの変更幅の上限**：暴落への無限追従を物理的に止める
- **ドライランモード**：最初の1〜2週間は「こう変更するはず」をログ出力するだけにして、
  実際の相場と突き合わせて検証してから書き込みを有効化する

**損益分岐**：プライスターは年63,360円。SP-API習得と実装に20〜30時間かかるとして、
時給2,500円換算で5〜7.5万円相当。**初年度はほぼトントン、2年目以降は自作が有利**。

### 14-5. 自作の本質的価値は「自分のルールを埋め込めること」

既製の価格改定ツールは基本的に「他の出品者に追従する」だけだが、自作なら本ドキュメントの
知見をそのままロジックにできる。

- **出品者数が急増したら値下げ追従を止め、早期損切りに切り替える**（9-3の値崩れ予測）
- 評価の低い出品者の価格は追従対象から除外する
- Amazon本体が出品してきたら撤退フラグを立てる（7-2）
- 在庫日数30日／60日で価格戦略を自動的に切り替える（11-6の撤退ルール）

7-5の「ツールの初期設定のまま使う人が増えるほど価格差が消える」という警鐘を踏まえると、
**自分専用のリプライスロジックを持つこと自体が差別化**になる。

> SP-APIの具体的なエンドポイント仕様は変更される可能性があるため、実装前に必ず公式ドキュメントを
> 確認すること。`ANY_OFFER_CHANGED` 通知でイベント駆動にする方法もあるが、SQSの設定が必要になるため、
> ローカル運用ならスケジュール実行によるポーリングの方が単純。

## 15. 第三者レビューを踏まえた計画の修正（2026年9月）

本ドキュメントの計画を別のAIに批判的レビューしてもらった結果を反映した章。
指摘のうち妥当と判断したものを取り込み、一部は再調査のうえ修正した。

### 15-1. 事実関係の訂正

| 項目 | 当初の記述 | 訂正後 |
|---|---|---|
| 楽天の規約 | 「転売目的の購入を禁止」 | 包括禁止とは言えない。ただし**楽天カード規約はせどり仕入れ目的の使用を明確に禁止**（9-4に詳述） |
| Amazon販売手数料 | 一律15%で計算 | カテゴリーにより異なる（概ね5〜15.4%程度）。**Revenue CalculatorでASIN単位に算出**すること |
| FBA手数料 | 固定588円 | サイズ・重量区分で変動（レビュアー提示の例：小型288円／標準318〜532円／大型589円〜。**要確認**） |
| 出品アカウント費用 | 「小口は登録料不要」 | **確認済み**：小口は月額登録料0円、商品ごとの基本成約料100円（税抜）。大口は月額4,900円（税抜）＋基本成約料なし。損益分岐は月49個（4,900円÷100円）。月50個以上なら大口が得 |

**別の書籍で「Amazon大口出品の月額登録料（約5,000円）が初期費用として必須」と紹介されていた例も
確認したが、これは不正確。** 月50個未満のスモールスタートなら小口出品の方が明確に安く、
**通常のFBA（Amazon販売向けの発送代行）は小口出品でも利用できる**。大口出品が必須になるのは
「FBAマルチチャネルサービス」（Amazon倉庫の在庫をAmazon以外の販路向け注文の発送に使う機能）
や、広告運用・Brand Registryなどブランド展開（OEM）に関わる機能を使う場合であり、
16章で見た「せどりの費用リストにOEM前提の要件が紛れ込む」パターンの一例と考えられる。

### 15-2. 粗利前提の感度分析（最重要の修正）

当初の設計は「粗利1,500円／個 × 20個」だったが、**この1,500円という前提が計画中で最も楽観的**
との指摘を受けた。妥当な指摘なので、前提を1点に固定せず幅で持つ形に改める。

| 1個あたり粗利 | 月3万円に必要な販売個数 | 備考 |
|---|---|---|
| 1,500円 | 20個 | 当初想定。達成できれば理想的 |
| 1,000円 | 30個 | **現実的な中央シナリオ** |
| 700円 | 約43個 | **大口アカウント（月49個目安）の検討圏に入る** |
| 500円 | 60個 | 工数が13章の想定を大きく超える |

**含意**：粗利が下振れすると必要個数が増え、リサーチ工数・納品工数・必要資金がすべて膨らむ。
さらに月49個を超えると大口アカウントへの切り替え判断が必要になる。
**計画は粗利1,000円を基準に立て、1,500円は上振れケースとして扱う**のが安全。

### 15-3. 仕入れ基準に「価格下落ストレステスト」を追加

楽天のセールで利益商品が見つかるとき、**他のせどらーも同時に仕入れている可能性が高い**。
その結果、FBAに納品した頃には出品者が増えて価格が下がっていることがある。
現在価格だけで判定すると、この構造を見落とす。

11-3の仕入れ基準に以下を追加する。

- **Amazon現在価格から10%下落しても利益が残るか**
- **20%下落しても赤字にならないか**
- 損益分岐価格（これを下回ったら赤字になる価格）を事前に算出しておく

20%下落テストを通らない商品は、価格競争が起きた時点で損切り確定になる。

### 15-4. 検証プロセスを4フェーズに再設計

当初のミニマム案は「3〜5個テスト仕入れ」だったが、
**それで分かるのはオペレーションが回るかだけで、収益性は判断できない**との指摘は正しい。
両者を分離し、さらに**資金を1円も使わないフェーズを先頭に追加**する。

#### Phase 0：机上リサーチ（資金0円・最重要）
- 楽天の商品100件程度をピックアップし、Keepa・Revenue Calculatorと照合して
  **11-3＋15-3の仕入れ基準を満たす商品が何件あるかを実測する**。
- 測る指標：**仕入れ基準通過率**、通過商品の平均粗利、1時間あたりの発見件数。
- 判断の目安：
  - 100件中15件前後が通過 → 手法として有望
  - 100件中3件程度 → 効率化（ツール導入）が前提になる
  - 100件中0〜1件 → **この手法自体を再考する**
- **金銭リスクゼロで、この副業の成否を決める最重要の数字が手に入る**。
  仕入れる前に必ずここを通す。
- 集計作業には `docs/phase0-kit/analyze.py` を使う。CSVに候補を記録すると、
  仕入れ基準通過率・平均粗利・1時間あたりの期待利益を自動計算してくれる（`docs/phase0-kit/README.md` 参照）。
- 実際に集めたデータとそこから得られた知見は `docs/phase0-kit/research-log/` に蓄積している。
  例えば2026-09-22の記録では、有名ブランドの日用品10件を調査した結果6件が全滅し、
  「有名すぎる定番ブランドはこの手法に向かない」という7-1・9-1の警告どおりのシグナルが
  実データで確認できた（詳細は同ディレクトリのREADME参照）。

#### Phase 1：動作確認（1か月・3〜5万円）
- 3〜5商品 × 各1〜2個。目的は**FBAを一周させること**であり、利益は度外視。
- 得られるもの：アカウント開設、FBA納品、販売、入金、実際の手数料額、実工数。

#### Phase 2：再現性確認（2〜3か月目）
- 候補100〜200商品規模で調査を回し、実測する：
  仕入れ基準通過率／実売利益／仕入れ後の価格下落率／販売までの日数／リサーチ所要時間。

#### Phase 3：事業判断
- 月利益額ではなく、**時給・投下資本利益率（ROI）・在庫回転**で判断する。
- 継続・自動化・撤退のいずれかを決める。撤退も正当な結論。

### 15-5. KPIの変更：金額ではなく「利益 ÷ 全作業時間」

9-1で最大の離脱要因が「利益と作業量のギャップ」であることを踏まえ、追跡する指標を変更する。

- **主KPI：利益 ÷ 全作業時間**（リサーチして何も見つからなかった時間も分母に含める）
  - 月3万円 ÷ 15時間 ＝ 2,000円/時 → 副業として成立
  - 月3万円 ÷ 35時間 ＝ 857円/時 → 事業として魅力が薄い
- **先行指標：リサーチ1時間あたりに発見できた利益商品の期待利益額**
  - 例）1時間で候補30件 → Keepa精査10件 → 基準通過2件 → 期待利益4,000円

**この副業の真のボトルネックはFBA納品作業ではなく「利益商品の発見能力」**である。
自動化や外注化を検討する前に、まずこの発見能力の実測値を持つこと。

### 15-6. レビューを受けても変えなかった点

- **「最初の目標は1個売って一周させること」という方針**：Phase 1として維持。
  ただしこれはオペレーションテストであり、収益性の判断材料ではないと明記した。
- **ツールの段階的導入（まずKeepaのみ）**：13-4の方針は変更なし。
  ただしPhase 0の結果次第では、早期に全頭検索ツールが必要と判明する可能性がある。
- **AIの役割分担（12章）**：方針は維持。ただし「仕入れ候補分析装置を自作する」という
  使い方（CSVを入力して利益・ROI・損益分岐価格・下落耐性を自動計算し、
  A：仕入れ候補／B：要確認／C：見送りに機械判定させる）は14-3の具体化として有効。

## 16. 情報源の信憑性を判定する（教材・書籍を読むときの視点）

この分野には「誰でも全自動で月利◯◯万円」と謳う教材が多く、Kindle本 → LINE登録 →
無料セミナー → 高額スクールという導線もよく使われる。構造自体は違法ではないが、
**参入障壁を低く見せるほど成約率が上がる**という利害関係が働く点は認識しておく。

### 16-1. 判定の5項目

1. **失敗事例・撤退理由が書かれているか**（本ドキュメントの9章に相当する内容があるか）
2. **規約・法令リスクに触れているか**（楽天カード規約、真贋調査、古物商許可、税務）
3. **コストが網羅されているか**（特に在庫リスクと変動費）
4. **数字の出所が示されているか**
5. **「誰でも」「全自動」「不労」の出現頻度**（多いほどマーケティング色が強い）

**重要**：1項目の欠落は編集方針で説明できるが、**複数項目が同じ方向（参入障壁を低く見せる方向）に
揃っている場合は構造的**と判断してよい。単純な誤りならプラス方向にも誤差が出るはずである。

### 16-2. 情報の種類ごとに信憑性は違う

一律に否定するのではなく、種類で分けて扱う。

| 情報の種類 | 信憑性 | 理由 |
|---|---|---|
| 制度・手数料・ツール機能 | 比較的高い | すぐ検証できるので嘘を書きにくい |
| 手順・ワークフロー | 中程度 | 一般論は成立するが、都合の悪い工程が省かれやすい |
| 費用・収益・工数の数字 | **低い** | 一方向にバイアスがかかりやすい |
| 「全自動」等の再現性の主張 | **最も低い** | 検証不能。12章の結論（判断・現物・決済は人力が残る）と矛盾する |
| 実績額の主張 | 検証手段がない | 月利300万円は利益率20%なら月商1,500万円規模＝個人副業の話ではない |

### 16-3. 実例：ある教材の初期費用リストの検証

「Amazonせどりの初期費用」として次の4項目が挙げられていた例。

| 記載項目 | 検証結果 |
|---|---|
| 大口出品 月約5,000円 | **数字は正しい**（月4,900円・税抜）。ただし月20個規模なら小口（1商品100円・税抜）の方が安く、初心者に大口は不要 |
| ブランドの商標登録費用 約5.5万円 | **せどりには不要**。商標が必要なのはOEM／自社ブランド販売。なお自己出願の実費は1区分で出願料12,000円＋登録料（5年17,200円／10年32,900円）＝約2.9〜4.5万円、弁理士依頼なら9.5〜23万円 |
| 商品の仕入れ代 | **最大の費用なのに金額が書かれていない** |
| 外注費用 数千円程度 | **非現実的に低い**。OEMなら商品リサーチ・画像・LP作成・輸入代行が必要で桁が違う |

**内部矛盾**：商標登録費用が入っているならOEMの話だが、
OEMの初期費用の実勢は雑貨で30万〜100万円、化粧品で100万〜300万円であり、桁が合っていない。

**完全に欠落していた費用**：販売手数料・FBA手数料（変動費）、ツール費用（13-4の試算で月1万円前後）、
在庫リスク、FBA長期保管手数料、税務コスト。

**教訓**：誤りの方向が「すべて安く見える方向」に揃っていた。これが16-1の判定基準そのものである。

### 16-4. 結論：他人の主張を検証するより自分で測る

「全自動で月利◯◯万円」が本当かどうかを判定する最短ルートは、レビューを探すことではなく、
**Phase 0（15-4）で楽天商品100件の通過率を自分で測ること**である。資金は0円で済み、
他人の言葉ではなく自分のデータで判断できる。
